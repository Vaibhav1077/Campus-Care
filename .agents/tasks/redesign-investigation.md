# CampusCare – Redesign Investigation Report

## 1. CSV Columns (`data/data.csv`)

| Column | Type / Purpose |
|---|---|
| `complaint_id` | String – unique identifier, format `C001`, `C002`, … (auto-generated by `generate_complaint_id`) |
| `date_reported` | String – date complaint was filed, format `YYYY-MM-DD` (required) |
| `hostel_block` | String – hostel block name / building (required) |
| `room_number` | String – room number or location label (required) |
| `category` | String – one of `Electrical`, `Plumbing`, `Cleaning`, `Furniture`, `Internet`, `Other` (required) |
| `description` | String – free-text problem description (required) |
| `reported_by` | String – name of the student who filed the complaint (required) |
| `contact` | String – phone/email of the reporter (optional) |
| `priority` | String – one of `Critical`, `High`, `Medium`, `Low` (required) |
| `status` | String – one of `Pending`, `In Progress`, `Resolved` (required) |
| `assigned_to` | String – name of maintenance staff assigned (optional) |
| `date_resolved` | String – resolution date, format `YYYY-MM-DD` (optional, populated when resolved) |
| `resolution_notes` | String – free-text notes from staff on how the issue was fixed (optional) |

The `CSV_COLUMNS` list in `data_manager.py` defines the canonical column order above.

## 2. Module Exports

### `modules/validators.py`

**Constants**
- `VALID_CATEGORIES: list[str]` – `["Electrical", "Plumbing", "Cleaning", "Furniture", "Internet", "Other"]`
- `VALID_STATUSES: list[str]` – `["Pending", "In Progress", "Resolved"]`
- `VALID_PRIORITIES: list[str]` – `["Critical", "High", "Medium", "Low"]`
- `REQUIRED_FIELDS: list[str]` – the eight fields that must be non-empty on every complaint

**Functions**

| Signature | Purpose |
|---|---|
| `validate_complaint(record: dict) -> tuple[bool, list[str]]` | Validates all required fields, date formats, and enum values. Returns `(is_valid, errors)`. |
| `generate_complaint_id(existing_ids: list[str]) -> str` | Finds the highest `C\d+` number and returns the next one (e.g. `C004`). |
| `detect_duplicate(new_record: dict, existing: pd.DataFrame) -> bool` | Returns `True` if a row with the same block + room + category + date already exists in the DataFrame. |

### `modules/data_manager.py`

**Constants**
- `CSV_COLUMNS: list[str]` – the 13-column ordered list (matches section 1 above).

**Functions**

| Signature | Purpose |
|---|---|
| `load_data(path: str) -> pd.DataFrame` | Reads the CSV; returns an empty DataFrame with correct columns if the file is missing or empty. All columns read as `str`. |
| `save_data(df: pd.DataFrame, path: str) -> None` | Atomic write (temp file + rename). Creates parent directories automatically. |
| `add_complaint(record: dict, path: str) -> tuple[bool, str]` | Generates ID if absent, validates, checks duplicate, appends to CSV. Returns `(success, message)`. |
| `update_complaint(complaint_id: str, updates: dict, path: str) -> tuple[bool, str]` | Finds row by `complaint_id`, applies `updates` dict (only columns in `CSV_COLUMNS`, never `complaint_id` itself). Returns `(success, message)`. |
| `delete_complaint(complaint_id: str, path: str) -> tuple[bool, str]` | Removes the row matching `complaint_id`. Returns `(success, message)`. |
| `get_complaint(complaint_id: str, df: pd.DataFrame) -> dict \| None` | Looks up a single complaint from an already-loaded DataFrame; returns a dict or `None`. |
| `export_csv(df: pd.DataFrame, filters: dict) -> str` | Applies a `{column: value}` filter dict (skips `"All"` values), returns CSV string ready for download. |

### `modules/priority_engine.py`

**Constants**
- `THRESHOLDS: dict` – configurable rule thresholds:
  - `age_medium_days: 7` – Low-base complaints pending > 7 days → Medium
  - `age_high_days: 14` – base ≤ Medium pending > 14 days → High
  - `age_critical_days: 30` – base ≥ Medium pending > 30 days → Critical
  - `recurring_window_days: 90` – lookback window for recurring detection
  - `recurring_min_count: 2` – minimum prior complaints to trigger recurring boost
  - `overdue_days: 7` – Pending/In Progress older than 7 days = overdue
- `PRIORITY_ORDER: list[str]` – `["Low", "Medium", "High", "Critical"]`
- `ELECTRICAL_CRITICAL_KEYWORDS: list[str]` – spark, shock, fire, smoke, etc.
- `PLUMBING_HIGH_KEYWORDS: list[str]` – flood, burst, sewage, etc.

**Functions**

| Signature | Purpose |
|---|---|
| `calculate_priority(record: dict, historical_df: pd.DataFrame) -> tuple[str, str]` | Returns `(priority_level, explanation)`. Applies three-step logic: (1) category/keyword base, (2) age escalation for Pending/In Progress, (3) recurring boost. Never escalates a Low-base complaint to Critical via age alone. |
| `get_overdue_complaints(df: pd.DataFrame) -> pd.DataFrame` | Returns rows where status is Pending/In Progress and age > `overdue_days`. |
| `get_critical_pending(df: pd.DataFrame) -> pd.DataFrame` | Returns rows where priority is Critical or High and status is Pending or In Progress. |

### `modules/analytics.py`

All functions accept a `pd.DataFrame` and handle `None` / empty gracefully (return zeroed dicts or empty DataFrames).

| Signature | Purpose |
|---|---|
| `summary_stats(df: pd.DataFrame) -> dict` | Returns KPIs: `total`, `pending`, `in_progress`, `resolved`, `critical`, `overdue`, `avg_resolution_days`. |
| `category_distribution(df: pd.DataFrame) -> pd.DataFrame` | Columns: `category`, `count`. Sorted descending. |
| `priority_distribution(df: pd.DataFrame) -> pd.DataFrame` | Columns: `priority`, `count`. |
| `status_distribution(df: pd.DataFrame) -> pd.DataFrame` | Columns: `status`, `count`. |
| `complaint_trend(df: pd.DataFrame) -> pd.DataFrame` | Columns: `week` (ISO week start), `count`. |
| `recurring_issues(df: pd.DataFrame) -> pd.DataFrame` | Groups by `hostel_block` + `room_number` + `category`; keeps groups with count ≥ 2. Columns: `hostel_block`, `room_number`, `category`, `count`. |
| `top_locations(df: pd.DataFrame) -> pd.DataFrame` | Columns: `hostel_block`, `count`. Sorted descending. |
| `avg_resolution_by_category(df: pd.DataFrame) -> pd.DataFrame` | Resolved complaints only. Columns: `category`, `avg_days`. |

## 3. Current `app.py` Pages / Sidebar Sections

The sidebar uses `st.radio` with five options:

| Nav Label | Description |
|---|---|
| `📊 Dashboard` | KPI metric cards (7 columns), bar/pie/line charts using `summary_stats`, `category_distribution`, `priority_distribution`, `status_distribution`, `complaint_trend`. Overdue alert banner. |

get_overdue_complaints(df: pd.DataFrame) -> pd.DataFrame

summary_stats(df: pd.DataFrame) -> dict   # keys: total, pending, in_progress, resolved, critical, overdue, avg_resolution_days
recurring_issues(df: pd.DataFrame) -> pd.DataFrame   # columns: hostel_block, room_number, category, count

# validators
VALID_CATEGORIES, VALID_STATUSES, VALID_PRIORITIES  # must stay identical
validate_complaint(record: dict) -> tuple[bool, list[str]]
```

### Role-based access requirements (from user request)

- **Student role**: register complaints (pre-fills `reported_by` from login), view only their own complaints, track status, see resolution notes.
- **Admin / Maintenance Staff role**: view all complaints, filter by hostel/category/priority/status, assign staff, update status/notes, access analytics and recurring reports.
- Login page must gate access; students must not reach admin pages.
- No new external dependencies — implement auth with `st.session_state` only.

### Data path constants (must remain unchanged)

```
